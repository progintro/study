# Κεφάλαιο 6: Εντολές και Ροή Ελέγχου

<!-- {% raw %} -->

> **Στόχοι:** μετά από αυτό το κεφάλαιο θα μπορείτε να
> - κατατάσσετε μια εντολή της C σε μία από τις πέντε κατηγορίες (κενή, έκφρασης,
>   σύνθετη, συνθήκης, επανάληψης)·
> - εξηγείτε τι κάνει η κενή εντολή `;` και πότε «κρύβεται» σε ένα πρόγραμμα·
> - γράφετε και να διαβάζετε εντολές `if`, `if-else` και αλυσίδες `else if`·
> - αναγνωρίζετε το πρόβλημα του dangling `else` και να το αποφεύγετε με αγκύλες·
> - γράφετε βρόχους με `while`, `for` και `do-while` και να προβλέπετε πόσες φορές
>   εκτελείται το σώμα τους·
> - σχεδιάζετε (και να διαβάζετε) το διάγραμμα ροής κάθε εντολής ελέγχου.

>
> **Χρόνος μελέτης:** ~2 ώρες

## Σύνοψη

Μέχρι τώρα τα προγράμματά μας εκτελούσαν τις εντολές τους μία προς μία, από πάνω
προς τα κάτω. Σε αυτή τη διάλεξη ολοκληρώνουμε την εικόνα για τις εντολές της C,
κατατάσσοντάς τες σε πέντε κατηγορίες (κενές, έκφρασης, σύνθετες, συνθήκης,
επανάληψης), και περνάμε στη **ροή ελέγχου**: στις εντολές που αποφασίζουν *ποια*
εντολή θα εκτελεστεί και *πόσες φορές*. Βλέπουμε την `if` και την `if-else`, τις
εμφωλευμένες `if` και την παγίδα του dangling `else`, και τους τρεις βρόχους της C:
`while`, `for` και `do-while`, ο καθένας με το διάγραμμα ροής του. Με αυτά τα
εργαλεία μπορούμε πλέον να γράψουμε προγράμματα που παίρνουν αποφάσεις και
επαναλαμβάνουν υπολογισμούς, δηλαδή σχεδόν οποιονδήποτε αλγόριθμο.

## Θεωρία

### Έλεγχος της λύσης σας με pipes και time

Η διάλεξη ξεκίνησε με μερικές πρακτικές συμβουλές για την άσκηση `aliquot` της
πρώτης εργασίας (hw0), οι οποίες όμως ισχύουν για κάθε πρόγραμμα που διαβάζει από
την πρότυπη είσοδο (stdin). Αντί να πληκτρολογείτε κάθε φορά τις τιμές εισόδου με το
χέρι, μπορείτε να τις «ταΐσετε» στο πρόγραμμα με μια σωλήνωση (pipe):

```sh
echo -e "138\n0\nf\n" | ./aliquot
```

Η `echo -e` τυπώνει το κείμενο ερμηνεύοντας τις ακολουθίες διαφυγής, οπότε κάθε
`\n` γίνεται αλλαγή γραμμής. Το `|` συνδέει την έξοδο της `echo` με την είσοδο του
`./aliquot`, το οποίο διαβάζει έτσι τρεις γραμμές: `138`, `0` και `f`, σαν να τις
είχατε πληκτρολογήσει εσείς. Αν βάλετε μπροστά από το πρόγραμμα την εντολή `time`,
το shell μετράει και πόσο χρόνο χρειάστηκε η εκτέλεση:

```sh
echo -e "138\n0\nf\n" | time ./aliquot
```

Μπορείτε ακόμα και να οπτικοποιήσετε την έξοδο, στέλνοντάς τη με ένα δεύτερο pipe
στο εργαλείο `ttyplot`, που σχεδιάζει στο τερματικό τους αριθμούς που δέχεται (ίσως
χρειαστεί να το εγκαταστήσετε πρώτα):

```sh
echo -e "2856\n0\nf\n" | ./aliquot | ttyplot
```

Για όσους ενδιαφέρονται για τα μαθηματικά πίσω από τις ακολουθίες aliquot, οι
διαφάνειες δίνουν και ένα σχετικό άρθρο (βλ. «Διάβασμα»). Για τα pipes και την
ανακατεύθυνση δείτε το [Κεφάλαιο 1](../01-command-line/).

### Κατηγορίες εντολών

Στην προηγούμενη διάλεξη ([Κεφάλαιο 5](../05-operators-statements/)) είδαμε τους
τελεστές και πώς από αυτούς φτιάχνονται εκφράσεις και εντολές. Εδώ ολοκληρώνουμε την
εικόνα: κάθε **εντολή (statement)** της C ανήκει σε μία από τις εξής πέντε
κατηγορίες:

| # | Κατηγορία | English | Παράδειγμα |
| --- | --- | --- | --- |
| 1 | Κενές εντολές | null / empty statements | `;` |
| 2 | Εντολές έκφρασης | expression statements | `x = 4;` |
| 3 | Σύνθετες εντολές | compound statements / blocks | `{ x = 4; y = 7; }` |
| 4 | Εντολές συνθήκης | conditional statements | `if (x > y) max = x;` |
| 5 | Εντολές επανάληψης | iteration statements / loops | `while (i < 42) i++;` |

Οι δύο τελευταίες κατηγορίες είναι οι εντολές ροής ελέγχου και αποτελούν το
μεγαλύτερο μέρος του κεφαλαίου.

### Η κενή εντολή

Η **κενή εντολή (empty / null statement)** δεν εκτελεί τίποτα· είναι αυτό που στα
αγγλικά λέγεται no-operation ή **no-op**. Αποτελείται μόνο από ένα semicolon:

```c
;       // null statement
;;;;;   // 5 null statements
```

Θυμηθείτε ότι στην C το semicolon (`;`) χρησιμοποιείται ως διαχωριστικό εντολών: δείχνει
πού τελειώνει μια εντολή. Ένα `;` χωρίς τίποτα πριν από αυτό είναι επομένως μια
ολόκληρη εντολή, απλώς άδεια.

Μόνη της η κενή εντολή είναι άχρηστη. Η χρησιμότητά της (και ο κίνδυνός της) φαίνεται
σε συνδυασμό με άλλες εντολές: η `if` και οι βρόχοι περιμένουν *μία* εντολή ως σώμα,
και μερικές φορές αυτή η εντολή είναι σκόπιμα (ή κατά λάθος!) η κενή. Θα δούμε
παρακάτω ότι ένα ξεχασμένο `;` μετά από `while (...)` μετατρέπει ολόκληρο τον βρόχο.

### Η εντολή έκφρασης

**Εντολή έκφρασης (expression statement)** στην C ονομάζουμε μια έκφραση που
τελειώνει με semicolon. Οι αναθέσεις, οι αυξήσεις και οι κλήσεις συναρτήσεων που
γράφουμε συνέχεια είναι όλες εντολές έκφρασης:

```c
x = 4;
y = 7;
z = ++y;
y = z - (x++);
z = x - (--y);
```

Οι διαφάνειες ρωτούν: *ποια είναι η τιμή των `x`, `y`, `z` μετά την εκτέλεση αυτών των
εντολών;* Για να απαντήσετε πρέπει να θυμηθείτε τη διαφορά ανάμεσα στην προθεματική
(`++y`, `--y`) και τη μεταθεματική (`x++`) μορφή των τελεστών αύξησης και μείωσης από
το [Κεφάλαιο 5](../05-operators-statements/): η προθεματική αλλάζει πρώτα τη μεταβλητή
και δίνει τη νέα τιμή, ενώ η μεταθεματική δίνει την παλιά τιμή και αλλάζει τη
μεταβλητή μετά. Κάντε την ιχνηλάτηση εντολή προς εντολή, σημειώνοντας σε έναν πίνακα
τις τρεις τιμές μετά από κάθε γραμμή· η απάντηση βρίσκεται στις ερωτήσεις
αυτοαξιολόγησης.

### Η σύνθετη εντολή (block)

**Σύνθετη εντολή (compound statement)** ή αλλιώς **block** λέγεται μια σειρά από
εντολές όταν περικλείονται σε αγκύλες `{ }`:

```c
{
    x = 4;
    y = 7;
    z = ++y;
    y = z - (x++);
    z = x - (--y);
}
```

Το σημαντικό είναι ότι, συντακτικά, ένα block μετράει ως **μία** εντολή. Όπου η
γραμματική της C ζητάει «μια εντολή» (για παράδειγμα ως σώμα μιας `if` ή μιας `while`)
μπορούμε να βάλουμε ένα block και να εκτελέσουμε έτσι όσες εντολές θέλουμε. Γι' αυτό
σχεδόν κάθε εντολή ροής ελέγχου που θα δείτε έχει αγκύλες. Προσέξτε ότι μετά την
κλειστή αγκύλη ενός block δεν χρειάζεται semicolon. Ένα block μπορεί επίσης να είναι
άδειο, `{ }`, οπότε κάνει ό,τι και η κενή εντολή.

### Ροή ελέγχου και διαγράμματα ροής

**Ροή ελέγχου (control flow)** λέγεται η σειρά με την οποία θα εκτελεστούν οι εντολές
σε ένα πρόγραμμα. Χωρίς ειδικές εντολές, η σειρά είναι απλώς αυτή με την οποία είναι
γραμμένες. Οι **εντολές ροής ελέγχου (control flow statements)** αλλάζουν αυτή τη
σειρά: παραλείπουν εντολές (συνθήκη) ή τις επαναλαμβάνουν (βρόχοι).

Η ροή ελέγχου συνήθως οπτικοποιείται με ένα **διάγραμμα ροής (flowchart)**. Στα
διαγράμματα των διαφανειών:

- ένα βέλος με την ετικέτα *execution* δείχνει από πού μπαίνει η εκτέλεση·
- ένας **ρόμβος** είναι ο έλεγχος μιας συνθήκης, με δύο εξόδους, «αληθής» και «ψευδής»·
- ένα **ορθογώνιο** είναι μια εντολή που εκτελείται·
- ένα μικρό τετράγωνο στο τέλος είναι το σημείο από όπου η εκτέλεση συνεχίζει με την
  επόμενη εντολή του προγράμματος.

Στις επόμενες ενότητες τα διαγράμματα αυτά έχουν ξαναγραφτεί ως κείμενο.

Υπενθύμιση από το [Κεφάλαιο 5](../05-operators-statements/): στην C μια συνθήκη είναι
απλώς μια έκφραση. Αν η τιμή της είναι **μηδέν**, θεωρείται **ψευδής**· αν είναι
**οτιδήποτε άλλο**, θεωρείται **αληθής**. Γι' αυτό μπορούμε να γράψουμε `while (1)` ή
`if (n)`.

### Η εντολή if

Η **εντολή `if` (if statement)** εκτελεί μια εντολή μόνο αν μια λογική συνθήκη είναι
αληθής. Η γενική μορφή της είναι:

```text
if ( συνθήκη )
    εντολή
```

Οι παρενθέσεις γύρω από τη συνθήκη είναι **υποχρεωτικές**: `if x > 1` είναι
συντακτικό λάθος. Το διάγραμμα ροής:

```text
          execution
              |
              v
        < ( συνθήκη ) >
         |           |
       ψευδής      αληθής
         |           |
         |           v
         |        [εντολή]
         |           |
         +-----+-----+
               |
               v
      (επόμενη εντολή)
```

Η «εντολή» μπορεί να είναι οποιουδήποτε είδους από τις πέντε κατηγορίες. Οι διαφάνειες
δείχνουν τρία παραδείγματα:

```c
if (year > 1)
    ;
```

```c
if (year > 1)
    year++;
```

```c
if (year > 1) {
    year++;
}
```

Στο πρώτο το σώμα είναι η κενή εντολή, οπότε η `if` δεν κάνει τίποτα όποια κι αν είναι
η τιμή του `year`. Στο δεύτερο το σώμα είναι μια εντολή έκφρασης. Στο τρίτο είναι
ένα block που περιέχει την ίδια εντολή έκφρασης· το δεύτερο και το τρίτο κάνουν
ακριβώς το ίδιο, αλλά η μορφή με τις αγκύλες είναι ασφαλέστερη, γιατί αν αργότερα
προσθέσετε δεύτερη εντολή στο σώμα θα μπει σίγουρα μέσα στην `if`.

### Η εντολή if-else

Η **εντολή `if-else`** επεκτείνει την `if` ώστε να εκτελεί μια *άλλη* εντολή όταν η
συνθήκη είναι ψευδής:

```text
if ( συνθήκη )
    εντολή1
else
    εντολή2
```

Ακριβώς μία από τις δύο εντολές θα εκτελεστεί, ποτέ και οι δύο και ποτέ καμία:

```text
          execution
              |
              v
        < ( συνθήκη ) >
         |           |
       ψευδής      αληθής
         |           |
         v           v
     [εντολή2]   [εντολή1]
         |           |
         +-----+-----+
               |
               v
      (επόμενη εντολή)
```

Το κλασικό παράδειγμα είναι ο υπολογισμός του μεγαλύτερου από δύο αριθμούς:

```c
if (x > y)
    max = x;
else
    max = y;
```

Οι διαφάνειες θέτουν εδώ τρεις ερωτήσεις για συζήτηση:

1. **Θα μπορούσαμε να «ζήσουμε» χωρίς `else`;** Ναι: μπορούμε πρώτα να δώσουμε στο
   `max` τη μία τιμή και να τη διορθώσουμε με μια απλή `if` αν χρειάζεται:

   ```c
   max = y;
   if (x > y)
       max = x;
   ```

   Το `else` δεν προσθέτει κάτι που δεν μπορεί να γίνει αλλιώς, κάνει όμως τον κώδικα
   πιο σαφή: διαβάζοντάς τον βλέπετε αμέσως ότι υπάρχουν δύο αποκλειόμενες περιπτώσεις.
2. **Υπάρχει εναλλακτικός τρόπος να γράψουμε το παραπάνω;** Ο τελεστής συνθήκης
   `? :` από το [Κεφάλαιο 5](../05-operators-statements/) κάνει ακριβώς αυτή τη
   δουλειά μέσα σε μία έκφραση: `max = (x > y) ? x : y;`.
3. **Τι κάνουμε όταν έχουμε πάνω από δύο συνθήκες;** Χρησιμοποιούμε εμφωλευμένες
   `if`, που είναι το θέμα της επόμενης ενότητας.

### Εμφωλευμένες if και η αλυσίδα else if

Πολλές φορές χρειάζεται να ελέγξουμε πάνω από μία συνθήκη. Επειδή το σώμα μιας `if`
ή ενός `else` μπορεί να είναι οποιαδήποτε εντολή, μπορεί να είναι και μια άλλη `if`.
Τότε λέμε ότι έχουμε **εμφωλευμένες εντολές `if` (nested if)**. Το παράδειγμα των
διαφανειών βάζει τιμή σε μια μεταβλητή `lab` ανάλογα με το έτος σπουδών `year`:

```c
lab = -1;
if (year < 1)
    { /* empty block */ }
else if (year == 1)
    lab = 20;
else
    lab = 0;
```

Διαβάστε το ως εξής: αν `year < 1`, δεν κάνουμε τίποτα (το σώμα είναι ένα άδειο block,
οπότε το `lab` μένει `-1`)· αλλιώς, αν `year == 1`, το `lab` γίνεται `20`· αλλιώς (δηλαδή
για `year > 1`) γίνεται `0`.

Τυπικά, το `else if` δεν είναι ξεχωριστή λέξη-κλειδί της C: είναι ένα `else` του οποίου η
εντολή τυχαίνει να είναι μια νέα `if`. Γράφοντάς τα στην ίδια γραμμή παίρνουμε μια
ευανάγνωστη **αλυσίδα `else if`**: οι συνθήκες ελέγχονται με τη σειρά, εκτελείται το
σώμα της *πρώτης* που βρίσκεται αληθής, και το τελικό `else` πιάνει όλες τις
υπόλοιπες περιπτώσεις.

### Το πρόβλημα του dangling else

Πολλές εμφωλευμένες `if` μπορούν να οδηγήσουν σε **αμφισημία (ambiguity)**, κάτι που
δεν μας αρέσει καθόλου στην επιστήμη των υπολογιστών. Οι διαφάνειες ρωτούν: *είναι τα
δύο παρακάτω προγράμματα ισοδύναμα;*

```c
lab = -1;
if (year < 1)
    { /* empty block */ }
else if (year == 1)
    lab = 20;
else
    lab = 0;
```

```c
lab = -1;
if (year <= 1)
    if (year == 1)
        lab = 20;
else
    lab = 0;
```

Η στοίχιση του δεύτερου προγράμματος υπονοεί ότι το `else` ανήκει στην εξωτερική `if
(year <= 1)`. Αν ήταν έτσι, τα δύο προγράμματα θα ήταν ισοδύναμα. Όμως ο μεταγλωττιστής
**αγνοεί τη στοίχιση**. Όταν ένα `else` θα μπορούσε να ανήκει σε δύο `if`, η C ακολουθεί
τον κανόνα: **κάθε `else` αντιστοιχεί στην πλησιέστερη προηγούμενη `if` που δεν έχει
ήδη `else`**. Εδώ αυτή είναι η εσωτερική `if (year == 1)`. Άρα το δεύτερο πρόγραμμα στην
πραγματικότητα σημαίνει:

```c
lab = -1;
if (year <= 1) {
    if (year == 1)
        lab = 20;
    else
        lab = 0;
}
```

Αυτό είναι το πρόβλημα του **dangling else** («κρεμασμένο else»). Αν δοκιμάσετε μερικές
τιμές, η διαφορά φαίνεται αμέσως:

| `year` | 1ο πρόγραμμα | 2ο πρόγραμμα |
| --- | --- | --- |
| `0` (ή αρνητικό) | `lab = -1` | `lab = 0` |
| `1` | `lab = 20` | `lab = 20` |
| `2` (ή μεγαλύτερο) | `lab = 0` | `lab = -1` |

Τα προγράμματα λοιπόν **δεν** είναι ισοδύναμα. Το μάθημα των διαφανειών είναι απλό:
**αν δεν είμαστε σίγουροι, χρησιμοποιούμε αγκύλες `{ }` για να υποδείξουμε τα όρια των
σύνθετων εντολών.** Αν θέλαμε το `else` να ανήκει στην εξωτερική `if`, θα γράφαμε:

```c
lab = -1;
if (year <= 1) {
    if (year == 1)
        lab = 20;
} else {
    lab = 0;
}
```

Ο gcc με `-Wall` σάς προειδοποιεί για τέτοιες περιπτώσεις με ένα μήνυμα όπως
`suggest explicit braces to avoid ambiguous 'else' [-Wdangling-else]`: μην το αγνοείτε.

### Βρόχοι: η εντολή while

Η δεύτερη μεγάλη οικογένεια εντολών ροής ελέγχου είναι οι **δομές επανάληψης**, ή
**βρόχοι (loops)**. Η απλούστερη είναι η **εντολή `while` (while statement)**, που
επαναλαμβάνει μια άλλη εντολή **όσο** η λογική συνθήκη είναι αληθής:

```text
while ( συνθήκη )
    εντολή
```

Η συνθήκη ελέγχεται **πριν** από κάθε επανάληψη. Αν είναι αληθής, εκτελείται η εντολή
(το **σώμα** του βρόχου) και η εκτέλεση γυρίζει πίσω στον έλεγχο· μόλις βρεθεί ψευδής,
η εκτέλεση συνεχίζει μετά τον βρόχο. Αν η συνθήκη είναι ψευδής από την αρχή, το σώμα
δεν εκτελείται **καμία** φορά.

```text
          execution
              |
              v
   +--> < ( συνθήκη ) >
   |     |           |
   |   ψευδής      αληθής
   |     |           |
   |     v           v
   |  (έξοδος)    [εντολή]
   |                 |
   +-----------------+
```

Κάθε επανάληψη του σώματος λέγεται και **επανάληψη (iteration)**. Για να τερματίσει
κάποτε ο βρόχος, το σώμα πρέπει να αλλάζει κάτι από το οποίο εξαρτάται η συνθήκη.

**Παράδειγμα #1: τι κάνει το παρακάτω πρόγραμμα;**

```c
#include <stdio.h>

int main() {
    int i = 0;
    int sum = 0;
    while (i < 42) {
        sum += i;
        i++;
    }
    printf("%d %d\n", i, sum);
    return 0;
}
```

Το `i` ξεκινάει από `0` και αυξάνεται κατά ένα σε κάθε επανάληψη, ενώ το `sum`
συσσωρεύει τις τιμές του `i`. Ο βρόχος σταματάει όταν η συνθήκη `i < 42` γίνει για
πρώτη φορά ψευδής, δηλαδή όταν `i == 42`. Επομένως έχουν προστεθεί οι αριθμοί
$0 + 1 + \dots + 41 = \frac{41 \cdot 42}{2} = 861$ και η έξοδος είναι:

```text
$ ./a.out
42 861
```

Προσέξτε ότι μετά τον βρόχο το `i` έχει την τιμή που *έκανε* τη συνθήκη ψευδή (42), όχι
την τελευταία τιμή για την οποία εκτελέστηκε το σώμα (41).

**Παράδειγμα #2: τι κάνει το παρακάτω;**

```c
while (1);
```

Η συνθήκη `1` είναι πάντα αληθής και το σώμα είναι η κενή εντολή. Πρόκειται για έναν
**ατέρμονα βρόχο (infinite loop)** που δεν κάνει τίποτα για πάντα: το πρόγραμμα
«κολλάει» και πρέπει να το σταματήσετε με Ctrl-C.

Οι διαφάνειες ρωτούν: *υπάρχει κάποια χρησιμότητα στο να έχουμε μια λογική συνθήκη που
είναι πάντα αληθής;* Ναι. Πολλά προγράμματα πρέπει να τρέχουν «για πάντα»: ένας web
server που περιμένει αιτήματα, ένα λειτουργικό σύστημα, ένα παιχνίδι που ξανασχεδιάζει
την οθόνη, ένα πρόγραμμα που διαβάζει είσοδο μέχρι να τελειώσει. Σε αυτά γράφουμε
συνήθως `while (1)` με χρήσιμο σώμα, και ο βρόχος είτε δεν τελειώνει ποτέ είτε
τερματίζεται από μέσα (π.χ. με `return`, ή με την `break` που θα δούμε σε επόμενη
διάλεξη).

**Παράδειγμα #3: τι κάνει το παρακάτω;**

```c
i = 0;
while (i < 42);
    printf("%d\n", i++);
```

Η στοίχιση υπονοεί ότι η `printf` είναι το σώμα του βρόχου, αλλά προσέξτε το `;`
αμέσως μετά το `while (i < 42)`. Αυτό το semicolon είναι μια κενή εντολή, και *αυτή*
είναι το σώμα του βρόχου. Άρα το `i` δεν αλλάζει ποτέ, η συνθήκη `0 < 42` μένει για
πάντα αληθής, και το πρόγραμμα κολλάει σε ατέρμονα βρόχο χωρίς να τυπώσει τίποτα. Η
`printf` θα εκτελούνταν μία φορά *μετά* τον βρόχο, αλλά δεν φτάνουμε ποτέ εκεί. Είναι
ένα από τα πιο κλασικά λάθη στη C: ο μεταγλωττιστής δέχεται τον κώδικα χωρίς
πρόβλημα, γιατί είναι συντακτικά σωστός.

### Η εντολή for

Η **εντολή `for` (for statement)** συγκεντρώνει σε μία γραμμή τα τρία συστατικά που
έχει σχεδόν κάθε βρόχος: αρχικοποιεί μεταβλητές, επαναλαμβάνει μια εντολή όσο η
λογική συνθήκη είναι αληθής, και στο τέλος κάθε επανάληψης εκτελεί το **βήμα**.
Γενική μορφή:

```text
for ( αρχικοποίηση ; συνθήκη ; βήμα )
    εντολή
```

Η σειρά εκτέλεσης είναι:

1. η **αρχικοποίηση** εκτελείται **μία φορά**, στην αρχή·
2. ελέγχεται η **συνθήκη**· αν είναι ψευδής, ο βρόχος τελειώνει·
3. αν είναι αληθής, εκτελείται η **εντολή** (το σώμα)·
4. εκτελείται το **βήμα** και η εκτέλεση επιστρέφει στο 2.

```text
          execution
              |
              v
       [Αρχικοποίηση]
              |
              v
   +--> < ( συνθήκη ) >
   |     |           |
   |   ψευδής      αληθής
   |     |           |
   |     v           v
   |  (έξοδος)    [εντολή]
   |                 |
   |                 v
   +------------- [Βήμα]
```

Το παράδειγμα των διαφανειών τυπώνει 100 φορές το ίδιο μήνυμα:

```c
int i;
for ( i = 0 ; i < 100 ; i++ )
    printf("Hello world\n");
```

Η `for` δεν προσθέτει κάτι που δεν μπορεί να κάνει η `while`: είναι απλώς πιο συμπαγής
γραφή. Ο βρόχος

```text
for ( αρχικοποίηση ; συνθήκη ; βήμα )
    εντολή
```

κάνει το ίδιο με τον

```text
αρχικοποίηση;
while ( συνθήκη ) {
    εντολή
    βήμα;
}
```

Το πλεονέκτημα της `for` είναι ότι όλη η «λογιστική» του βρόχου (από πού ξεκινάμε, πότε
σταματάμε, πώς προχωράμε) φαίνεται με μια ματιά στην πρώτη γραμμή.

**Τι κάνει το `for (;;)`;** Και τα τρία μέρη της `for` είναι προαιρετικά· τα δύο `;`
όμως πρέπει να υπάρχουν πάντα. Όταν λείπει η συνθήκη, θεωρείται πάντα αληθής. Άρα

```c
for (;;)
    ;
```

είναι, όπως και το `while (1);`, ένας ατέρμονας βρόχος. Το `for (;;)` είναι μάλιστα η
κλασική γραφή του ατέρμονα βρόχου στη C.

**Γενικό παράδειγμα.** Ο πιο συνηθισμένος βρόχος που θα γράψετε είναι αυτός που
μετράει από `0` μέχρι κάποιο όριο `N`:

```c
int i;
for ( i = 0 ; i < N ; i++ ) {
    printf("%d\n", i);
}
```

Οι διαφάνειες ρωτούν:

- *Πόσες φορές θα εκτελεστεί το block εντολών μέσα στην `for`;* Ακριβώς `N` φορές (αν
  `N` είναι θετικό), για `i = 0, 1, …, N-1`. Αν `N <= 0`, η συνθήκη είναι ψευδής από
  την αρχή και το σώμα δεν εκτελείται καθόλου.
- *Θα τυπωθεί το `N`;* Όχι. Όταν το `i` γίνει `N`, η συνθήκη `i < N` είναι ψευδής και ο
  βρόχος τελειώνει πριν από την `printf`. Η τελευταία τιμή που τυπώνεται είναι `N-1`.
- *Τι θα συμβεί αν αλλάξω την αρχικοποίηση ή το βήμα;* Αλλάζει το πλήθος και οι τιμές
  των επαναλήψεων. Για παράδειγμα, με `i = 1` το σώμα εκτελείται `N-1` φορές, με
  βήμα `i += 2` τυπώνονται μόνο οι ζυγοί αριθμοί από `0` έως κάτω από `N`, και με
  βήμα `i--` το `i` απομακρύνεται από το `N`, οπότε ο βρόχος (θεωρητικά) δεν
  τελειώνει ποτέ.

Το μοτίβο `for (i = 0; i < N; i++)` αξίζει να γίνει δεύτερη φύση: ξεκινάμε από το 0,
συγκρίνουμε με `<` και παίρνουμε ακριβώς `N` επαναλήψεις.

### Η εντολή do-while

Η **εντολή `do-while` (do-while statement)** τρέχει πρώτα **μία φορά** την εντολή και
στη συνέχεια ελέγχει τη λογική συνθήκη για να αποφασίσει αν χρειάζεται άλλη
επανάληψη:

```text
do
    εντολή
while ( συνθήκη );
```

Προσέξτε το semicolon στο τέλος: εδώ είναι **υποχρεωτικό**, σε αντίθεση με την απλή
`while`. Στο διάγραμμα ροής η εντολή βρίσκεται *πριν* από τον ρόμβο της συνθήκης, και
αυτή είναι όλη η διαφορά από την `while`:

```text
          execution
              |
              v
   +----> [εντολή]
   |          |
   |          v
   |    < ( συνθήκη ) >
   |     |           |
   +-- αληθής      ψευδής
                     |
                     v
                 (έξοδος)
```

Επειδή ο έλεγχος γίνεται στο τέλος, το σώμα της `do-while` εκτελείται **τουλάχιστον
μία φορά**, ακόμα κι αν η συνθήκη είναι ψευδής από την αρχή.

**Παράδειγμα: τι κάνει το παρακάτω πρόγραμμα;**

```c
i = 0;
do
    i++;
while (i < 42);
printf("%d\n", i);
```

Το `i` αυξάνεται (πρώτα σε `1`, μετά σε `2`, …) και μετά από κάθε αύξηση ελέγχεται αν
είναι ακόμα μικρότερο του `42`. Όταν γίνει `42`, ο έλεγχος αποτυγχάνει και ο βρόχος
τελειώνει. Το πρόγραμμα τυπώνει:

```text
42
```

Αν αλλάξετε την αρχικοποίηση σε `i = 100;`, η `do-while` θα εκτελέσει το σώμα μία φορά
και θα τυπώσει `101`, ενώ ένα αντίστοιχο `while (i < 42) i++;` δεν θα εκτελούσε το σώμα
καθόλου και θα τύπωνε `100`. Η `do-while` είναι φυσική επιλογή όταν η πρώτη εκτέλεση
πρέπει να γίνει οπωσδήποτε, για παράδειγμα όταν διαβάζουμε μια τιμή από τον χρήστη
και την ξαναζητάμε όσο είναι άκυρη.

### Σύγκριση των τριών βρόχων

Η διάλεξη έκλεισε με ένα Kahoot πάνω σε αυτά τα θέματα. Για επανάληψη, η παρακάτω
σύνοψη συγκεντρώνει τις διαφορές των τριών βρόχων:

| | `while` | `for` | `do-while` |
| --- | --- | --- | --- |
| Πότε ελέγχεται η συνθήκη | πριν από κάθε επανάληψη | πριν από κάθε επανάληψη | μετά από κάθε επανάληψη |
| Ελάχιστες εκτελέσεις σώματος | 0 | 0 | 1 |
| Αρχικοποίηση / βήμα | γράφονται χωριστά | μέσα στην επικεφαλίδα | γράφονται χωριστά |
| `;` μετά τη συνθήκη | λάθος (κενό σώμα) | λάθος (κενό σώμα) | υποχρεωτικό |
| Ατέρμονας βρόχος | `while (1)` | `for (;;)` | `do … while (1);` |

Όπου η επανάληψη ελέγχεται από έναν μετρητή με γνωστό εύρος, η `for` είναι συνήθως η
πιο ευανάγνωστη επιλογή. Όπου επαναλαμβάνουμε «όσο ισχύει κάτι» χωρίς προφανή
μετρητή, ταιριάζει η `while`. Όπου το σώμα πρέπει να τρέξει τουλάχιστον μία φορά,
ταιριάζει η `do-while`. Οι υπόλοιπες εντολές ροής ελέγχου της C (`switch`, `break`,
`continue`) δεν καλύπτονται σε αυτή τη διάλεξη· η ροή ελέγχου συνεχίζεται στο
[Κεφάλαιο 8](../08-control-flow-2/).

## Κύρια σημεία

1. Κάθε εντολή της C ανήκει σε μία από πέντε κατηγορίες: κενές εντολές, εντολές
   έκφρασης, σύνθετες εντολές, εντολές συνθήκης και εντολές επανάληψης.
2. Η κενή εντολή `;` δεν κάνει τίποτα (no-op)· η χρησιμότητα και ο κίνδυνός της
   φαίνονται όταν γίνεται σώμα μιας `if` ή ενός βρόχου.
3. Μια έκφραση που τελειώνει σε `;` είναι εντολή έκφρασης· το semicolon δείχνει πού
   τελειώνει η εντολή.
4. Μια σειρά εντολών μέσα σε `{ }` είναι μια σύνθετη εντολή (block) και μετράει
   συντακτικά ως μία εντολή, οπότε μπορεί να γίνει σώμα οποιασδήποτε εντολής ελέγχου.
5. Ροή ελέγχου είναι η σειρά εκτέλεσης των εντολών· την καθορίζουν οι εντολές ροής
   ελέγχου και συνήθως την οπτικοποιούμε με διάγραμμα ροής.
6. Η `if` εκτελεί μια εντολή μόνο αν η συνθήκη είναι αληθής (μη μηδενική)· οι
   παρενθέσεις γύρω από τη συνθήκη είναι υποχρεωτικές.
7. Η `if-else` εκτελεί ακριβώς μία από δύο εντολές, ανάλογα με τη συνθήκη.
8. Για περισσότερες από δύο περιπτώσεις χρησιμοποιούμε εμφωλευμένες `if`, συνήθως
   γραμμένες ως αλυσίδα `else if`.
9. Ο μεταγλωττιστής αγνοεί τη στοίχιση: κάθε `else` ανήκει στην πλησιέστερη
   προηγούμενη `if` χωρίς `else` (dangling else).
10. Αν δεν είμαστε σίγουροι, χρησιμοποιούμε αγκύλες `{ }` για να υποδείξουμε τα όρια
    των σύνθετων εντολών.
11. Η `while` ελέγχει τη συνθήκη πριν από κάθε επανάληψη, οπότε το σώμα της μπορεί να
    μην εκτελεστεί καθόλου.
12. Ένα `;` αμέσως μετά από `while (...)` ή `for (...)` γίνεται το σώμα του βρόχου και
    συνήθως οδηγεί σε ατέρμονα βρόχο ή σε κώδικα που εκτελείται μόνο μία φορά.
13. Βρόχοι με πάντα αληθή συνθήκη (`while (1)`, `for (;;)`) είναι χρήσιμοι για
    προγράμματα που τρέχουν συνεχώς ή τερματίζουν από το εσωτερικό του βρόχου.
14. Η `for` συγκεντρώνει αρχικοποίηση, συνθήκη και βήμα· είναι ισοδύναμη με μια
    `while` και ο βρόχος `for (i = 0; i < N; i++)` εκτελείται ακριβώς `N` φορές.
15. Η `do-while` εκτελεί το σώμα τουλάχιστον μία φορά, γιατί ελέγχει τη συνθήκη στο
    τέλος· το `;` μετά το `while (...)` της είναι υποχρεωτικό.
16. Με pipes (`echo -e "..." | ./prog`) δοκιμάζετε γρήγορα ένα πρόγραμμα με έτοιμη
    είσοδο, και με `time` μετράτε πόσο χρόνο χρειάζεται.

## Συχνά λάθη

- **Semicolon μετά τη συνθήκη βρόχου.** `while (i < 42); printf("%d\n", i++);`: το
  πρόγραμμα κολλάει χωρίς έξοδο, γιατί το σώμα είναι η κενή εντολή. Το ίδιο με
  `for (i = 0; i < N; i++);`, όπου το «σώμα» εκτελείται μόνο μία φορά, μετά τον
  βρόχο. Διόρθωση: σβήστε το `;` και βάλτε το σώμα σε `{ }`.
- **Semicolon μετά από `if (...)`.** `if (x > y); max = x;`: η ανάθεση γίνεται πάντα.
  Διόρθωση: κανένα `;` ανάμεσα στο `)` και στο σώμα.
- **Εμπιστοσύνη στη στοίχιση.** Γράφετε δύο εντολές με εσοχή κάτω από μια `if` χωρίς
  αγκύλες· μόνο η πρώτη ανήκει στην `if`, η δεύτερη εκτελείται πάντα. Διόρθωση: `{ }`.
- **Dangling else.** Ένα `else` που «φαίνεται» να ανήκει στην εξωτερική `if` πάει στην
  εσωτερική και τα αποτελέσματα βγαίνουν λάθος για κάποιες τιμές· ο gcc με `-Wall`
  λέει `suggest explicit braces to avoid ambiguous 'else'`. Διόρθωση: αγκύλες.
- **Παράλειψη των παρενθέσεων.** `if x > 1` ή `while i < 42` δεν μεταγλωττίζεται
  (`expected '(' before 'x'`). Οι παρενθέσεις της συνθήκης είναι υποχρεωτικές.
- **Ξεχασμένο βήμα σε `while`.** Ο μετρητής δεν αυξάνεται μέσα στο σώμα, οπότε ο
  βρόχος δεν τελειώνει ποτέ. Διόρθωση: βεβαιωθείτε ότι κάτι στο σώμα οδηγεί τη
  συνθήκη προς το ψευδές.
- **Λάθος κατά ένα (off-by-one).** `for (i = 0; i <= N; i++)` εκτελείται `N+1` φορές,
  όχι `N`. Διόρθωση: ξεκινήστε από 0 και συγκρίνετε με `<`, ή μετρήστε ξανά τις
  επαναλήψεις για τα άκρα.
- **Ξεχασμένο `;` στο τέλος της `do-while`.** `do i++; while (i < 42)` χωρίς `;`
  δίνει `expected ';'`. Εδώ το semicolon χρειάζεται.
- **Ανάγνωση του μετρητή μετά τον βρόχο.** Μετά το `while (i < 42) { … i++; }` το `i`
  είναι `42`, όχι `41`. Προσοχή όταν χρησιμοποιείτε τη μεταβλητή του βρόχου μετά από
  αυτόν.

## Ερωτήσεις αυτοαξιολόγησης

1. Ποιες είναι οι τιμές των `x`, `y`, `z` μετά τις εντολές `x = 4; y = 7; z = ++y; y = z - (x++); z = x - (--y);`;[^q1]
2. Πόσες εντολές περιέχει η γραμμή `;;;;;` και τι κάνουν;[^q2]
3. Γιατί ένα block `{ … }` μπορεί να σταθεί ως σώμα μιας `if`, ενώ δύο σκέτες εντολές όχι;[^q3]
4. Γράψτε τον υπολογισμό του `max` από τα `x`, `y` με τρεις τρόπους.[^q4]
5. Σε ποια `if` ανήκει ένα `else` όταν υπάρχουν δύο υποψήφιες και δεν υπάρχουν αγκύλες;[^q5]
6. Ποια είναι η διαφορά ανάμεσα σε `while` και `do-while`; Δώστε μια περίπτωση όπου δίνουν διαφορετικό αποτέλεσμα.[^q6]
7. Γράψτε έναν βρόχο `while` ισοδύναμο με το `for (i = 0; i < 100; i++) printf("Hello world\n");`.[^q7]
8. Πόσες φορές εκτελείται το σώμα του `for (i = 0; i <= N; i++)`;[^q8]
9. Τι κάνει το `for (;;)` και γιατί μεταγλωττίζεται αφού λείπουν και τα τρία μέρη;[^q9]

[^q1]: `z = ++y` κάνει `y = 8`, `z = 8`· `y = z - (x++)` κάνει `y = 8 - 4 = 4` και `x = 5`· `z = x - (--y)` κάνει `y = 3` και `z = 5 - 3 = 2`. Τελικά `x = 5`, `y = 3`, `z = 2`.
[^q2]: Πέντε κενές εντολές· καμία δεν κάνει τίποτα (no-op).
[^q3]: Η `if` δέχεται ως σώμα μία εντολή. Ένα block είναι συντακτικά μία (σύνθετη) εντολή, ενώ δύο σκέτες εντολές είναι δύο: μόνο η πρώτη ανήκει στην `if`.
[^q4]: Με `if-else`· με `max = y; if (x > y) max = x;`· με τον τελεστή συνθήκης `max = (x > y) ? x : y;`.
[^q5]: Στην πλησιέστερη προηγούμενη `if` που δεν έχει ήδη `else`, ανεξάρτητα από τη στοίχιση.
[^q6]: Η `while` ελέγχει τη συνθήκη πριν από το σώμα (0 ή περισσότερες εκτελέσεις), η `do-while` μετά (τουλάχιστον μία). Με `i = 100`, το `do i++; while (i < 42);` αφήνει `i = 101`, ενώ το `while (i < 42) i++;` αφήνει `i = 100`.
[^q7]: `i = 0; while (i < 100) { printf("Hello world\n"); i++; }`
[^q8]: `N + 1` φορές (για `i = 0, …, N`), αν `N >= 0`.
[^q9]: Είναι ατέρμονας βρόχος. Και τα τρία μέρη της `for` είναι προαιρετικά (αρκεί να υπάρχουν τα δύο `;`) και η συνθήκη που λείπει θεωρείται πάντα αληθής.
